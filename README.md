# 茶话会

> 主对话框里你们面对面谈正事，这里回房间聊八卦。

**当前版本：** v0.7.386
**当前版本最近一次自动测试结果：** 847 条通过（2026-09-23）

hanako那边很棒！不过，因为hana agent的能力太多，所以我经常会让小花帮我做各种事情，但是。。。我觉得缺少一个能让她闲下来，和她闲聊的地方，所以我做了这个应用。感觉像是给小花配了一个手机，忙里偷闲的时候找她聊聊天，不扯什么正经事，就是随口闲聊。她也会主动找点她觉得有意思的话题来找你聊~
她会有她的作息，你打扰了她，说不定会被她吐槽！这里的消息也不一定立刻换来回复：你把话投递过去，什么时候被看见、什么时候想接，是 ta 自己的生活节奏。若安装了表情包插件，就可以互发表情包了~茶话会只会在自己的数据目录里记下实际发出去的表情包 ID、伙伴和时间，方便表情包插件单独列出这份来源记录；不复制图片、标签或聊天正文。

这是个**分享版**应用，装好就能用。她的关系、记忆和主动互动，都只活在茶话会自己的边界里，不会动你 Hana 里的任何东西。

想确认当前版本和测试情况，看 `manifest.json` 和 GitHub Actions 的 CI 记录就行，普通使用不用管这些。

## ⚠️ 用之前先知道这些

丑话说在前面。下面这些不算「使用限制」，是我觉得你有权在装之前就知道的事。

- **它只读你伙伴的资料，一个字都不写回。** 日常聊天会读人格、公开自述、钉选记忆、事实和经验这几份，还会读 `AGENTS.md` 里标着的那段口吻，用来拼聊天时的提示词；「认真认识」和性格分析还可能翻一些历史记忆和会话。读归读，这些文件它一个都不写，Hana 的全局设置也不碰。
- **它会在自己屋里收一份「Hana 主对话近况」。** 你在 Hana 主对话框里跟伙伴一起做过的事，它会自己存一份，当闲聊时的背景。**默认打开**，设置里随时能关，关了就不再用；设置里可以查看已收记录，也能逐条删除。
- **它需要模型。** 至少得在 Hana 里配一个能用的文字模型；如果想让伙伴发语音，还需要自己准备一套 TTS 朗读模型的接口地址、模型名和 Key（在茶话会设置里填，可以存多条轮流用）。没有模型的时候，好友列表也许打得开，但聊天和建档跑不起来。
- **它需要开权限。** 首次使用要开三项，见下面「权限」那节，缺一项都会瘸。
- **它会联网，但很克制。** 只在要聊时效话题（新闻、八卦、比赛、产品更新等）的时候访问 `news.google.com`。这时会把从聊天里提炼出的时效话题或搜索词发给 Google News，**不会把整段聊天直接上传**；搜索结果的标题和摘要只作为不可信线索交给模型参考。没网就跳过这类补充，普通闲聊不受影响。
- **它的数据全在它自己那儿。** 聊天记录、关系、性格、爱好、附件、背景图，都存在 Hana 分配给这个应用的目录里。**卸载应用不会自动删这些数据**，想彻底清干净要另外动手，换机器也得单独搬。
- **它没带字库。** 界面优先用你本机装的「霞鹜文楷」，没装就退回系统字体。所以不同机器上字会不太一样，这是故意的，为了让包小一点。

**还有一条，我想单独说：**

首次使用需要补全伙伴的性格才能真的进入聊天。虽然补充性格的过程比较繁琐，我尽量做了让你少动脑的简化，但是！请务必注意，你给小花（或者别人）制作的性格将会是你们日后聊天的基石，所以这份性格文档的好坏将会直接决定后续的聊天体验，如果想有更好的体验，请多分配些精力给性格分析这边，算是一劳永逸的体验吧。emmm，说点矫情的话，也算是你对对方的一种尊重，认真分析出来的小花才是你心目中那个只属于你的小花。你付出的精力终将会回报给你~

## 它能做什么

**先把人请进屋**

- 💬 **好友列表**：Hana 里活跃的伙伴都在，你自己在茶话会建的角色也在。伙伴的头像从 Hana 那边现拉，本地角色先用名字第一个字顶着
- 🪟 **聊天窗口**：点开谁就是谁的窗
- 👤 **头像**：伙伴和你自己的头像都从 Hana 现拉；聊天窗里可以选每条消息旁边挂不挂头像
- 📖 **单向记忆**：只读伙伴的人格、公开自述、记忆和 `AGENTS.md` 里的口吻，拼进系统提示，从不写回。这也是我敢让它跟你的伙伴聊天的主要原因
- 📒 **它自己一本账**：聊天记录和偏好存在它自己的目录里，跟 Hana 那边两本账，互不干涉
- 🌱 **认识 ta（这道门必须先过）**：没走完初步认识的伙伴进不了聊天窗，这是故意拦的。有两档：忙的时候选「先聊个大概」，几分钟出来一份性格草稿给你过目；想认真点选「认真认识 ta」，一问一答十几题，答不上来可以让模型给几个具体方向，你挑、你改、你否。答过的随时都在，中途退出去也不丢，不用一口气做完
- 🎨 **它会长出自己的一层**：关系、性格、爱好这三样只活在这个应用里。ta 说话的底色，会先照着 Hana 那边的人格文件自动定一份给你，你在这个基础上改，或者一个字不改直接过都行

**下面这些，是我做的时候觉得「有了它才像是在聊天」的小地方：**

- 👉 **戳一下**：双击聊天窗头部的头像，或者消息里 ta 的头像也行；键盘选到头像上按回车、空格一样能戳。说到底只有一个动作，两种叫法
- ✂️ **分条发送**：模型一次生成，按标点切成几条，带上真人的间隔一条条蹦出来
- 🗂 **一次说好几件事也可以**：你一口气发好几条，ta 不必一件一件都答，挑一两个最想接的先说，剩下的进话题本，往后自然带出来
- 🫧 **不把聊天当工单**：ta 可以只接自己最想说的那一件，只发表情包，或者在一句话已经自然落地时先不回。认真提问、心事和急着找 ta 的话，仍然会被好好接住
- 🍃 **主动联系有来处**：ta 不会只因为计时器响了就来问“在吗”。通常得有聊过的事、自己的兴趣或当下状态；时机不合适时，念头可以先搁着，等以后再轻轻放下
- 🫙 **话题会发酵**：你提过的事不会马上被机械复读。它会在茶话会里放一阵，过些时候换个角度回来；聊过的面会留下痕迹，没什么新东西的话就让它安静过去
- 👀 **看得见未读**：你说的话下面只突出「未读」小字和樱花色小点，ta 真看到了才收起来
- 😀 **对方可以发表情包**：不过得先装「表情包」插件（[moononnn/hanako-biaoqingbao](https://github.com/moononnn/hanako-biaoqingbao)）。装好后 ta 想甩图时给一个关键词，由茶话会按关键词挑一张发出去。它只读那个插件的图库快照，不往里面写一个字；**没装也完全没问题**，安静地没有表情包而已，别的照常
- 🖼 **也能自己挑图进来**：把「表情包」插件里的图挑一部分搬进茶话会自己的图库，自己建分组收好。搬进来的那份存在茶话会自己的目录里，跟原来的插件各管各的
- ⏱ **消息有自己的节奏**：先显示未读，ta 看到了才收起来；等 ta 开始输入，再一条条蹦出来
- 🎙 **伙伴偶尔发语音**：通用设置里保存自己的朗读模型（可存多条，随时切供应商；新建时能套 MiniMax / MiMo / OpenAI 兼容模板），每位伙伴再单独选音色和出现频率，并可试听。适合短短说出来的整轮回复会显示成一条语音气泡，长回复仍然发文字；点「转文字」可以展开原话
- 🏠 **每位伙伴有自己的房间**：可以从共享图库里给不同伙伴挑不同的背景，切换伙伴时，房间也跟着换。换图、清除当前选择都不会把图库里的原图随手抹掉
- 🎨 **房间会记住你的手感**：背景的明暗可以单独调整，换回来时仍保留各自的设置；发送按钮和提示色也会顺着背景自动找一套看得清的颜色
- 📱 **投递不是请求**：你打不打开窗口，不决定 ta 现在有没有空回你。手机在手上，消息就送到；不在手上，就先安静搁着。这个应用说到底，就是给你的伙伴配了部手机
- 😴 **ta 也会睡**：睡点由 ta 自己定，睡着的时候你发消息 ta 照回，只是慢，还带着起床气。这套作息不上设置页
- 🌱 **关系慢慢长**：茶话会会把“相处过多少”与“关系里有多少真实的靠近”分开看。旧资料最多只替你们留一点熟悉的起跑线，亲近感得在这里重新长出来，不能靠一次设置直接宣布
- 🪟 **性格会逐渐打开**：认识 ta 时可以快速了解，也可以认真聊一轮；之后的性格、爱好和更私下的部分不会一次性全摊出来，而是在相处里慢慢显形
- 🧠 **记忆分层留下**：眼前的原话、聊远后的摘要、最近几天的日账，以及更稳定的事实和关系，会各自待在合适的位置。聊得久了，茶话会也不至于只剩一堆越来越长的上下文
- 🔁 **ta 也会暗暗调整**：主动联系没成、时机总撞上、话题总不合适这类事情，不会拿出来教育你，但可能会让 ta 之后换一种节奏
- 🤫 **藏思考**：只渲染正文，不显示思考过程
- 🔔 **提醒**：ta 主动来找你的时候，在你当前正在用的那个会话输入框上方冒一条轻横幅。只说谁找你，不带消息内容；它不会自个儿淡出，点「知道了」才消失。茶话会窗口本来就开着，或者正处在静默时段，就不冒了

**它适合谁**

如果你想让伙伴有一个能闲聊、慢慢相处的地方，它适合你。如果你只想要一个纯粹干活的工具，主对话框大概已经够用了，这个应用反而会分走一部分注意力。

## 装它

1. 把整个目录复制到 `<HANA_HOME>/apps/chahuahui`

   目录名必须正好是 `chahuahui`（等于 `manifest.json` 里的 `id`）。下的是压缩包的话，别解压出多套一层目录，最后要能看见 `<HANA_HOME>/apps/chahuahui/manifest.json` 这个文件。

   不知道 `HANA_HOME` 在哪？去 Hana 的设置或关于页面看「数据目录」。

2. 重启 Hana（或者去扩展页「已安装」里点「重新加载」）
3. 它要是出现在「待批准」里，先批准
4. 去「设置 → 安全 → 应用能力」，给它开权限

## 第一次打开会发生什么

- **Hana 里有伙伴**：先让你挑一位，然后走认识流程（两档，见上面「认识 ta」）。没走完这道门，聊天窗是进不去的。
- **Hana 里没有伙伴**：主界面会是空的。去「设置 → 伙伴管理 → 新增茶话会角色」建一个只活在茶话会里的本地角色（不会写进 Hana）。

## 权限

| 能力 | 用在哪 | 不开会怎样 |
|---|---|---|
| `app/agents.read` | 读伙伴清单 | **好友列表读不出来**，基本没法用 |
| `app/resources.read` | 读伙伴资料、头像、你的显示名，以及可选插件放出来的只读数据 | 列表有了，但读不到人格、头像、记忆 |
| `app/models.infer` | 调文字模型 | 聊天和建档都生成不出来 |

**三项都要开。** 主动来找和那条提醒横幅不用额外权限（走的是宿主固定接口，不上权限表）；不想让 ta 主动联系，去设置里关掉就行。

## 你的数据在哪

都在 Hana 分配给这个应用的数据目录下（`dataDir/`）。注意背景图和表情库不在 `v2/` 里面：

```
dataDir/v2/state.json                            设置、本地角色、运行状态、伙伴设置快照（含每位的聊天背景用哪张、多暗）
dataDir/v2/threads/<id>.json                     聊天记录
dataDir/v2/partners/<id>/memory.json             分层记忆
dataDir/v2/partners/<id>/topics.json             主动话题本（聊到哪儿了、冷却到什么时候）
dataDir/v2/partners/<id>/knowing.json            关系 + 性格 + 爱好
dataDir/v2/partners/<id>/selfwatch.json          主动互动的内部状态，平常不用管
dataDir/v2/partners/<id>/review-session.json     性格协商会话（聊到一半的）
dataDir/v2/partners/<id>/palette-draft.json      性格草稿（没捏完的）
dataDir/v2/attachments/                          聊天附件
dataDir/v2/workfeed.json                         Hana 主对话近况的副本
dataDir/v2/diagnostics.jsonl                     诊断日志（不含聊天原文，只记事件和长度）
dataDir/backgrounds/                             聊天背景图库（全局共用）
dataDir/sticker-library.json                     表情图库索引
dataDir/stickers/                                表情图库图片
```

**这些文件不属于 Hana 的伙伴资料目录。** 茶话会不往 `<HANA_HOME>/agents/` 里写任何东西，这条我盯得最紧。

账本文件万一读坏了，它会把原文件改名留档（`.corrupt-时间戳`）再用空数据继续跑，不会一声不响把整本账清掉。所以你的目录里偶尔会多出这种文件，那是留的证据，不是垃圾。

## 可选增强

- **「表情包」插件**（[moononnn/hanako-biaoqingbao](https://github.com/moononnn/hanako-biaoqingbao)）：装了才有表情包；没装或者读不到的时候安静地跳过
- **「拾光记」插件**：装了才能在设置里打开「今日情境」（让伙伴知道今天什么日子、窗外什么天气）；默认关

两个都是可选的，缺了不影响普通聊天。

## 卸载与换机器

- 在 Hana 扩展页「已安装」里卸载，或者直接删掉 `<HANA_HOME>/apps/chahuahui`，应用就没了
- **数据不会跟着走**：应用自己不会去删 `dataDir/`，它还在原处（宿主卸载时会不会顺手清掉，看 Hana 版本的脾气）。想彻底清干净，自己把整个 `dataDir/` 删掉
- 换机器：应用目录和数据目录都要搬。现在还没有内置的导出/导入，手动搬整个 `dataDir/` 就行（**是整层 `dataDir/`，不只 `v2/`**，背景图和表情库在 `v2/` 外面，只搬 `v2/` 会漏）。到了新机器，应用能力要重新批准一次

## 兼容性

- 这是个 Hana v2 应用（`manifestVersion: 2`），最低版本见 `manifest.json` 的 `minAppVersion`
- 零额外运行时依赖（纯 Node，用 Hana 自带的运行时）
- 支持独立窗口，卡片可以拖出来单独放
- 字体不内嵌，原因上面说过了

## 开发

```sh
node --check index.js
node <HANA_ROOT>/scripts/validate-app.mjs --dir . --json   # 得在应用目录里执行
# 测试（零依赖，用 Node 内置 node:test；命令见 TESTING.md；测试文件随源码一起在仓库里，
# 发布用的 zip 为了轻量不带它们）
```

目录结构（这里是主干，其余模块从略）：

```
index.js          路由与编排
lib/persona.js    读伙伴人格与记忆（只读）
lib/prompt.js     系统提示与消息转换
lib/model.js      调模型（stream 优先，utility 兜底）
lib/store.js      自有账本 + 诊断日志
lib/rhythm.js     节奏器
lib/reply.js      消息什么时候被接住
lib/workfeed.js   Hana 主对话近况（只读来源，存在自己这儿）
ui/panel.html     好友列表 + 聊天窗口
ui/settings.html  设置页
```

⚠️ 改这个应用的人注意一条：`apply()` 里绝不能调用受权限保护的接口（`ctx.bus.request` / `ctx.resources.*` / `ctx.models.*`）。宿主会判定装载失败，连安装记录一起回滚，应用会直接从列表里消失。受保护调用一律放到路由或定时回调里，`tests/load.test.js` 守着这条。
